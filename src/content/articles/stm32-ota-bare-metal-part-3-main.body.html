This post walks through the bootloader entry point. After reset, main() either honors an app-requested OTA flag, jumps a verified signed slot, or sits in the UART OTA receiver — then retries after idle timeout.

1. Boot decision flow

reset
  → enable IRQ, init clocks/GPIO/UART
  → if OTA flag set → clear flag → boot_enter_ota() / ota_run()
       (if OTA returns on idle timeout, fall through)
  → if boot_pick_slot() OK → delay 50 ms → jump_to_application()
  → else → boot_enter_ota()
  → while (1):
       → pick OK → jump
       → else → boot_enter_ota() again

There is no 3-second UART key window in the bootloader. To force OTA from a running app, the app sets the OTA flag and resets (see Part 14). Host tools enter OTA the same way, or by catching a boot with no valid image / after a timed-out OTA session.

2. Helpers in main.c

  • _write — retargets printf to uart1_write so logs go out USART1.
  • boot_pick_slot — tries active then inactive slot via boot_verify_slot() (SHA-256 + ECDSA). First success wins; returns 0 and fills jump_addr.
  • boot_enter_ota — prints OTA RX ready, calls ota_run(OTA_IDLE_TIMEOUT_MS), then prints OTA idle timeout when the receiver returns.

3. main() step by step

__asm volatile("cpsie i");
init();
SystemClock_Config();
GPIO_Init();
Uart1_Init();
printf("STM32F103 Bootloader\r\n");

if (ota_flag_is_set()) {
    (void)ota_flag_clear();
    boot_enter_ota();          /* may return on idle timeout */
}

if (boot_pick_slot(...) == 0) {
    delay_ms(50);
    jump_to_application(jump_addr);
    printf("Jump failed\r\n");
} else {
    printf("No valid signed app\r\n");
}

boot_enter_ota();

while (1) {
    if (boot_pick_slot(...) == 0) {
        delay_ms(50);
        jump_to_application(jump_addr);
    }
    boot_enter_ota();
}
  1. IRQ on — interrupts may have been off in startup; enable before UART IRQ RX.
  2. Board bring-up — clock, PC13 LED, USART1 — same driver stack the app uses.
  3. OTA flag — the app writes magic 0xDEADBEEF at OTA_CONFIG_ADDR then resets. Bootloader clears the flag and enters OTA immediately. If ota_run() returns (idle timeout), execution continues into the pick/jump path below — there is no else that skips pick forever.
  4. Normal boot — verify active then inactive; on success, short delay then jump_to_application(). A successful jump does not return; if it does, you see Jump failed.
  5. No valid image — print No valid signed app, then enter OTA.
  6. Retry loop — after any OTA idle timeout, try boot_pick_slot again (a finished OTA may have written a new signed image), otherwise re-enter OTA.

4. Why this shape

The flag path is for in-field updates while an app is already running: set flag, reset, bootloader goes straight to the UART receiver. Dual-slot verify-before-jump is the safety net: a bad OTA never becomes the execution image. The infinite loop after the first OTA session lets a timed-out transfer recover once a valid slot appears, without needing another power cycle.
