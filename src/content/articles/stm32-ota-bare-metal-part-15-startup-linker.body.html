OTA only works if every image is linked where the Flash map says it lives. Wrong ORIGIN → wrong vector addresses → app_is_valid_at fails or the jump hard-faults.

1. Flash map (64 KB Blue Pill)

/* bootloader.h */
#define BOOTLOADER_START  0x08000000UL
#define BOOTLOADER_SIZE   0x00005800UL   /* 22 KB */

#define APP1_START        0x08005800UL
#define APP1_SIZE         0x00005200UL   /* 20.5 KB */

#define APP2_START        0x0800AA00UL
#define APP2_SIZE         0x00005200UL   /* 20.5 KB */

#define OTA_CONFIG_ADDR   0x0800FC00UL   /* last 1 KB page */

Each app slot stores a 256-byte IMG1 header (IMG_HEADER_SIZE = 0x100) then the payload. Payload / vector-table addresses:

  • APP1 — 0x08005800 + 0x100 = 0x08005900
  • APP2 — 0x0800AA00 + 0x100 = 0x0800AB00

The linker FLASH ORIGIN for an app build must be that payload address, not the slot base. Signing prepends the header so the programmed slot image starts at APPn_START.

2. Bootloader linker

ENTRY(Reset_Handler)

_estack = ORIGIN(RAM) + LENGTH(RAM);

MEMORY
{
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 22K
}
  1. FLASH at 0x08000000 — after every reset the CPU fetches MSP / PC from here, so the bootloader always runs first.
  2. 22 KB — matches BOOTLOADER_SIZE; leaves room for two app slots + config.
  3. RAM 20 KB — full SRAM; stack at top via _estack.

Sections follow the Cube style: .isr_vector first in FLASH, then .text / .rodata, .data loaded into RAM (LMA in Flash), .bss zeroed at runtime.

3. Application linker

The repo’s default app script links for APP2:

MEMORY
{
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
  /* APP2 payload = APP2_START(0x0800AA00) + IMG_HEADER(0x100) */
  FLASH (rx)  : ORIGIN = 0x0800AB00, LENGTH = 0x5100
}
  • ORIGIN 0x0800AB00 — vector table and Reset_Handler symbols resolve into the APP2 payload region.
  • LENGTH 0x5100 — payload budget inside the 20.5 KB slot after the 256-byte header (0x5200 - 0x100).
  • Same RAM — app reuses the full 20 KB once the bootloader has jumped away.

application/Inc/conf.h must agree:

/* Must match linker FLASH ORIGIN (APP1=0x08005900, APP2=0x0800AB00) */
#define APP_FLASH_ORIGIN 0x0800AB00UL

To build for APP1 instead: change FLASH ORIGIN to 0x08005900, set APP_FLASH_ORIGIN the same way, and keep length under the remaining slot size. Part 14’s ota_request_enter() uses that define to guess OTA_SLOT_APP1 vs APP2.

4. Startup — vector table and Reset_Handler

Bootloader and application both ship Cube-style startup_stm32f103c8tx.s. The important piece for OTA is where .isr_vector is linked, not custom assembly.

4.1 g_pfnVectors

  .section .isr_vector,"a",%progbits
g_pfnVectors:
  .word _estack
  .word Reset_Handler
  .word NMI_Handler
  .word HardFault_Handler
  /* … Cortex-M3 + STM32F103 IRQ slots … */
  .word USART1_IRQHandler
  /* … */

Word 0 = initial MSP; word 1 = reset entry (Thumb). Peripheral IRQs are weak aliases to Default_Handler until a C file defines e.g. USART1_IRQHandler.

For the bootloader, this table sits at 0x08000000. For the app, the same section lands at 0x08005900 or 0x0800AB00. Absolute addresses inside the table (handler pointers) are fixed at link time to that ORIGIN — so you cannot flash an APP1 .bin into APP2 without rebuilding.

4.2 Reset_Handler

Reset_Handler:
  ldr r0, =_estack
  mov sp, r0
  bl SystemInit

  /* copy .data: _sidata → [_sdata, _edata) */
  /* zero .bss: [_sbss, _ebss) */

  bl __libc_init_array
  bl main

LoopForever:
  b LoopForever
  1. Load stack from linker _estack.
  2. SystemInit (weak in the startup; may be a real C stub).
  3. Copy initialized data from Flash LMA into RAM; clear BSS.
  4. Run C++ static constructors / libc init, then main.

5. Jump time: remap VTOR

After reset the CPU always uses the table at 0x08000000. When the bootloader jumps, it points VTOR at the payload address so app IRQs hit the app’s table:

/* bootloader.c — jump_to_application() */
SCB_VTOR = app_addr;   /* e.g. 0x0800AB00 */
/* set MSP from *(app_addr), bx to *(app_addr + 4) */

app_is_valid_at() checks that MSP looks like SRAM (0x2000xxxx), that the reset vector lies inside the slot, and that the Thumb bit is set — before VTOR / MSP / branch.

6. Takeaway

Bootloader: link at 0x08000000 / 22 KB. App: link at payload offset (0x08005900 or 0x0800AB00), keep APP_FLASH_ORIGIN in sync, sign so the header occupies the 256 bytes below that. Startup is standard; OTA correctness comes from matching ORIGIN, VTOR, and the dual-slot map.
