Series: STM32F103 Bare-Metal Secure OTA Bootloader — Part 1: Overview & Architecture.

Source: bootloader/tools/keygen.py in STM32F103C8T6-ota-base-metal.

This post walks through keygen.py line by line. Think of the OTA trust model as three jobs that share one key pair:

  1. keygen.py (setup, once) — derive an ECDSA P-256 key pair from a fixed seed, then write the public key only into C source (boot_pubkey.c). That public key is baked into the bootloader when you flash it.
  2. sign_image.py / main.py --sign (on the PC, every release) — take the app binary, hash it, and sign the hash with the private key. The private key never goes on the MCU; it stays on the PC and is derived again via the same derive_signing_key() helper from keygen.py. Output is a slot image: header (with signature) + payload.
  3. Bootloader verify.c (on the MCU, every boot / OTA) — recompute the payload hash and run ECDSA verify against the baked-in bootloader_pubkey[64]. Match → jump to the app. Fail → reject the image (tampered bytes, wrong signer, or pubkey out of sync).

In short: keygen stamps the public key onto the chip; sign_image seals each firmware with the private key; verify.c checks that seal before running code. This post focuses on the first job — how keygen.py builds that trust anchor.

1. Where it fits

keygen.py                          (PC, setup)
    └── writes boot_pubkey.c       → public key baked into bootloader Flash

sign_image.py / main.py --sign     (PC, each firmware build)
    └── import derive_signing_key() from keygen.py   → same private key
    └── hash payload + sign → IMG1 header ‖ app.bin

bootloader verify.c                (MCU, each boot / OTA)
    └── ECDSA verify(pubkey, hash, signature) → accept or reject

Private and public keys match because both sides call the same seed-based derivation. After running keygen.py you must rebuild and reflash the bootloader. Images signed before a key change will no longer verify.

2. Dependencies and constants

Full script (~45 lines):

#!/usr/bin/env python3
"""Generate bootloader_pubkey.c from deterministic dev fixture key."""

from __future__ import annotations

import hashlib
import sys
from pathlib import Path

KEY_SEED = b"stm32-bare-metal-dev-fixture"
OUT_C = Path(__file__).resolve().parent.parent / "lib" / "boot" / "src" / "boot_pubkey.c"
  • KEY_SEED — fixed byte string used to derive the private key. Same seed always yields the same key pair (handy for tutorials and CI). Not for production — anyone who knows the seed can sign firmware.
  • OUT_C — output path resolved relative to the script: bootloader/lib/boot/src/boot_pubkey.c. Parent of tools/ is bootloader/, then lib/boot/src/.
  • ecdsa — Python package (pip install ecdsa). Uses curve NIST256p (same as ECDSA P-256 / secp256r1 on the MCU).

3. derive_signing_key()

def derive_signing_key() -> SigningKey:
    priv = int.from_bytes(hashlib.sha256(KEY_SEED).digest(), "big") % NIST256p.order
    if priv == 0:
        priv = 1
    return SigningKey.from_secret_exponent(priv, curve=NIST256p)

One line of code turns a string into a private key. The pipeline is seed → digest → scalar:

  • Seed — the raw input you choose: KEY_SEED = b"stm32-bare-metal-dev-fixture". Same seed always yields the same key pair. It is not yet a key; it is just a fixed byte string.
  • Digest — SHA-256(seed), a fixed-length 32-byte hash. Hashing spreads the seed into a uniform-looking bit string of the size ECDSA expects, instead of using the seed bytes directly.
  • Scalar — that digest interpreted as a big integer, then reduced with % NIST256p.order so it lies in the valid range for the curve. This integer priv is the ECDSA private key d. On the curve, public key = d · G.

Why mention production? In this tutorial the seed is public in the repo, so anyone can re-derive the same private key and forge “valid” signatures. That is fine for learning. In a real product you would not do this:

  • Secret material — keep the real private key (or the secret used to derive it) offline or in a signing server, never in Git.
  • HSM (Hardware Security Module) — a dedicated box or cloud service that holds the private key and performs signing inside the device so the key never leaves. Your build pipeline asks the HSM to sign; it returns only the signature bytes.
  • KDF / HKDF — a dedicated “recipe” for turning a secret into a private key. This tutorial takes a shortcut: run SHA-256 once on the string "stm32-bare-metal-dev-fixture" and treat the result as the key. That is easy to follow in code, but weak: the string is short, public, and a single hash is not how production keys are meant to be made. A real setup often uses HKDF (one kind of KDF): you give it a long random secret that nobody else knows, plus optional context such as product id or key version, and HKDF outputs the private key. From one master secret you can derive different keys per product or key rotation without ever putting that master secret in the firmware repo.

This post still uses the simple seed→digest→scalar path so the code stays short and deterministic. Step by step in the function:

  1. SHA-256 the seed — hashlib.sha256(KEY_SEED).digest() produces the 32-byte digest.
  2. Interpret as integer — int.from_bytes(..., "big") treats those bytes as an unsigned big-endian integer.
  3. Reduce modulo curve order — % NIST256p.order makes the scalar valid for secp256r1 (order ≈ 2256). Without this, the value could be out of range and key creation would fail.
  4. Reject zero — private key 0 is invalid; force to 1 if the modulo result is 0 (extremely unlikely with this seed).
  5. Build SigningKey — SigningKey.from_secret_exponent(priv, curve=NIST256p) creates the object used later to sign (sign_image.py) or to extract the public key (main()).

This function is imported by sign_image.py so signing and verification always use the same deterministic dev key — no separate key file on disk.

4. main() — emit boot_pubkey.c

def main() -> int:
    sk = derive_signing_key()
    pub = sk.get_verifying_key().to_string()

    lines = ["/* Auto-generated by tools/keygen.py — do not edit */", "#include <boot_pubkey.h>", ""]
    lines.append("const uint8_t bootloader_pubkey[64] = {")
    for i in range(0, 64, 8):
        chunk = ", ".join(f"0x{b:02X}" for b in pub[i : i + 8])
        lines.append(f"    {chunk},")
    lines.append("};")
    lines.append("")

    OUT_C.write_text("\n".join(lines), encoding="utf-8")
    print(f"Wrote {OUT_C}")
    return 0
  • get_verifying_key().to_string() — returns 64 raw bytes: 32-byte X coordinate + 32-byte Y coordinate (uncompressed public point, no 0x04 prefix). This matches what lib/crypto expects in bootloader_pubkey[64].
  • C array formatting — loops in steps of 8 bytes per line for readability. Each byte is 0xNN uppercase hex.
  • Overwrite boot_pubkey.c — the file is regenerated entirely; manual edits are lost (header comment warns this).

Example output (first lines):

/* Auto-generated by tools/keygen.py — do not edit */
#include <boot_pubkey.h>

const uint8_t bootloader_pubkey[64] = {
    0x9E, 0xDF, 0x13, 0xD9, 0x7B, 0xB6, 0xC6, 0xE6,
    ...
};

Header boot_pubkey.h only declares extern const uint8_t bootloader_pubkey[64]; — verify code includes this and passes the array to micro-ecc ECDSA verify.

5. Link to sign_image.py

Signing is the second job from the intro. sign_image.py imports the same helper so the private key used on the PC matches the public key already in Flash:

from keygen import derive_signing_key

def build_header(payload: bytes, version: int) -> bytes:
    digest = sha256(payload)
    sk = derive_signing_key()
    signature = sk.sign_digest(digest, sigencode=...)

Flow on the PC: hash the app payload with SHA-256 → sign the 32-byte digest with the derived private key → pack digest + signature into the 256-byte IMG1 header, then append the payload.

Flow on the MCU (verify.c): recompute SHA-256 of the payload, then ECDSA-verify the 64-byte (r, s) against bootloader_pubkey. If keygen.py was never run (or the bootloader was not reflashed after a key change), verify fails and the image is rejected — that is intentional.

6. How to run

cd bootloader/tools
pip install -r requirements.txt
python keygen.py

Expected output: Wrote .../bootloader/lib/boot/src/boot_pubkey.c. Then rebuild the bootloader project in STM32CubeIDE and flash with ST-Link.

7. Security notes

  • Dev fixture only — the seed stm32-bare-metal-dev-fixture is public in the repo. Treat signed images as integrity-checked for learning, not as anti-cloning in the field.
  • Production — generate a unique key pair per product line (or per device with secure element), store private key offline or in a signing server, embed only the public key in firmware. Never commit production private keys.
  • Key rotation — change KEY_SEED (or use random key generation), run keygen.py, reflash bootloader, resign all deployable images.
