Source under bootloader/lib/crypto/: inc/crypto/crypto.h, sha256.h, uECC.h, src/crypto.c, sha256.c, uECC.c (plus micro-ecc includes: asm_arm.inc, curve-specific.inc, …). Verify call sites live in bootloader/lib/boot/src/verify.c.

Before the bootloader jumps to a slot — and again at the end of a successful OTA — it must prove the image was built by someone who holds the matching private key (Part 2). That proof is: SHA-256 of the payload, then ECDSA P-256 verify of the header signature over that hash.

1. What sits in lib/crypto

  • sha256.c / sha256.h — compact software SHA-256 (init / update / final).
  • uECC.c + headers / *.inc — micro-ecc, built for Cortex-M3. This project uses the secp256r1 curve only for verify.
  • crypto.c / crypto.h — the three functions verify.c actually calls. They run the SHA-256 API and uECC_verify, and expose a constant-time compare for digests.

2. Public API — crypto.h

void crypto_sha256(const uint8_t *data, uint32_t len, uint8_t out[32]);
int  crypto_memcmp_ct(const uint8_t *a, const uint8_t *b, uint32_t len);
int  crypto_ecdsa_p256_verify(const uint8_t pubkey[64],
                              const uint8_t hash[32],
                              const uint8_t signature[64]);
  • crypto_sha256 — one-shot hash: write 32 bytes to out.
  • crypto_memcmp_ct — returns 0 if equal, non-zero if different; runs in time independent of where the first mismatch is.
  • crypto_ecdsa_p256_verify — returns 1 if the signature is valid for that pubkey/hash (micro-ecc convention), else 0.

Sizes match the IMG1 header from later parts: 32-byte digest, 64-byte signature (r‖s), 64-byte uncompressed public key (X‖Y) from bootloader_pubkey.

3. crypto.c — what each call does

void crypto_sha256(const uint8_t *data, uint32_t len, uint8_t out[32])
{
    sha256_ctx_t ctx;

    sha256_init(&ctx);
    sha256_update(&ctx, data, len);
    sha256_final(&ctx, out);
}

int crypto_memcmp_ct(const uint8_t *a, const uint8_t *b, uint32_t len)
{
    uint8_t diff = 0U;
    uint32_t i;

    for (i = 0U; i < len; i++) {
        diff |= (uint8_t)(a[i] ^ b[i]);
    }
    return (int)diff;
}

int crypto_ecdsa_p256_verify(const uint8_t pubkey[64],
                             const uint8_t hash[32],
                             const uint8_t signature[64])
{
    return uECC_verify(pubkey, hash, 32U, signature, uECC_secp256r1());
}
  1. Hash — allocate a context on the stack, feed all len bytes (the payload may be tens of KB mapped in Flash), finalize into out[32].
  2. Compare — OR of all XOR differences; no early return on the first mismatch (avoids a timing leak when checking digests).
  3. Verify — ask micro-ecc to check ECDSA on secp256r1 with a 32-byte message hash. Pubkey is the raw 64-byte X‖Y form micro-ecc expects (not SEC1 0x04‖X‖Y).

4. SHA-256 implementation sketch

Context from sha256.h:

typedef struct {
    uint8_t  data[64];
    uint32_t datalen;
    uint64_t bitlen;
    uint32_t state[8];
} sha256_ctx_t;

void sha256_init(sha256_ctx_t *ctx);
void sha256_update(sha256_ctx_t *ctx, const uint8_t *data, uint32_t len);
void sha256_final(sha256_ctx_t *ctx, uint8_t hash[32]);

sha256_init loads the FIPS initial H0…H7 constants into state[]. sha256_update copies input into a 64-byte block buffer; every full block runs sha256_transform (message schedule + 64 compression rounds with the standard k[] constants). sha256_final appends the 0x80 padding, the 64-bit big-endian bit length, runs the last transform(s), and writes the 32-byte digest big-endian — the same digest the host keygen / image tool puts in the IMG1 header.

You can hash Flash in place: pass (const uint8_t *)payload_addr and payload_size without copying the image into RAM.

5. micro-ecc — ECDSA verify only

uECC.h declares:

int uECC_verify(const uint8_t *public_key,
                const uint8_t *message_hash,
                unsigned hash_size,
                const uint8_t *signature,
                uECC_Curve curve);

uECC_Curve uECC_secp256r1(void);

The bootloader never calls uECC_sign or uECC_make_key on device — signing stays on the host (Part 2). On the MCU we only need verify, which keeps the trust model simple: the public key is compiled into the bootloader; the private key never leaves the build machine.

uECC.c pulls in ARM-friendly field arithmetic via asm_arm.inc / platform-specific.inc and curve parameters via curve-specific.inc. You do not need to read that whole file to follow the boot path; the contract is the return value of uECC_verify.

6. End-to-end path in boot_verify_slot

crypto_sha256((const uint8_t *)payload_addr, payload_size, computed);

if (crypto_memcmp_ct(computed, hdr->sha256, 32U) != 0) {
    return -11;
}

if (crypto_ecdsa_p256_verify(bootloader_pubkey, computed, hdr->signature) != 1) {
    return -12;
}

*out_jump_addr = payload_addr;
return 0;
  1. Parse the IMG1 header and locate the payload inside the slot (Part 11 covers the header layout).
  2. Sanity-check the vector table at payload_addr (app_is_valid_at).
  3. Hash every payload byte into computed[32].
  4. Match header digest — if hdr->sha256 ≠ computed, reject (-11). This catches bit flips and mismatched headers before the slower ECDSA step.
  5. ECDSA — verify hdr->signature over computed with bootloader_pubkey. Fail → -12.
  6. Only then return the jump address (start of the signed payload / vector table).

Why hash-then-sign: the signature covers a fixed 32-byte digest, not the raw firmware blob. RAM stays small (one SHA context + micro-ecc stack), and the header can carry both the digest and the 64-byte signature for the host and device to agree on.

7. Takeaway

Integrity = SHA-256 over Flash-mapped payload. Authenticity = ECDSA P-256 verify with the baked-in public key. crypto.c is the only surface verify.c needs; underneath it is local SHA-256 plus micro-ecc’s uECC_verify(..., uECC_secp256r1()).
